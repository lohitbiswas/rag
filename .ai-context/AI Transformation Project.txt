1. Executive Summary
Brightter Inc. manages a significant volume of historical RFP responses and proposal documents within its SharePoint environment. While this repository represents valuable institutional knowledge, retrieving relevant content for new RFPs remains a manual and time-intensive process. Teams must search across multiple documents, identify applicable sections, and reconstruct responses-resulting in inefficiencies and inconsistent turnaround times.

To address this challenge, INT will design and implement a chat-based AI knowledge retrieval solution that enables Brightter's users to access historical proposal content through natural language queries. The solution will intelligently search indexed SharePoint documents and generate consolidated responses grounded in Brightter's own historical materials.

Rather than introducing complex document production workflows, the solution focuses on accelerating access to institutional knowledge while preserving Brightter's existing offline proposal preparation process. Users will review generated responses and retain full ownership of final document drafting outside the system.

This approach delivers measurable operational value by:

? Reducing time spent manually searching historical proposals
? Improving response consistency across RFP submissions
? Leveraging existing institutional knowledge more effectively
? Maintaining human control over final proposal content
? Integrating securely within Brightter's Microsoft ecosystem

Through this focused implementation, INT will enable Brightter Inc. to transition from manual knowledge searching to an AI-assisted retrieval model that improves efficiency while maintaining governance and professional oversight.

2. Project Objective
The project involves designing and implementing a workflow-driven AI application integrated with the organization's Microsoft ecosystem (primarily SharePoint-based repositories). The system will function as a structured document production platform rather than a conversational assistant.

The application will support a defined lifecycle: ingestion of historical documents, classification of incoming RFPs, template-based response generation using contextual retrieval, human review and approval, and controlled document export. The solution will also support aggregation of research inputs from approved sources to produce analytical narratives and enable generation of structured reports for internal and client use.

Key functional areas include:


? Knowledge repository ingestion and contextual retrieval
? Template-driven proposal drafting with AI assistance
? Check-in/check-out editing and approval workflow
? Research data aggregation and insight generation
? Report creation and controlled distribution
? Training and governed adoption

The platform will operate as a secure internal application with role-based access and human-in-the-loop validation, ensuring professional accuracy and compliance while improving efficiency across the advisory lifecycle.

5. Solution Scope of Work
5.1. Overview
INT will design, develop, and deploy a chat-based knowledge retrieval solution for Brightter
Inc., integrated with Brightter's existing SharePoint environment.

The solution will enable Brightter's internal users to retrieve relevant historical RFP responses and proposal content through a natural language conversational interface. Historical documents stored in designated SharePoint libraries will be ingested, indexed, and transformed into a searchable knowledge base to support contextual retrieval.

When a user submits a question within the chat interface, the system will interpret the query, search indexed historical documents, and retrieve the most relevant content segments. Based on the retrieved context, the system will generate a consolidated response grounded in Brightter's own documented knowledge. The generated response will be displayed within the chat interface for user review.

Users will retain full control over final proposal preparation by manually copying the generated response and incorporating it into their offline document drafting process.

The implementation scope includes:

? Integration with designated SharePoint repositories
? Document ingestion and indexing of historical RFP and proposal content
? Natural language query processing
? Contextual content retrieval
? AI-assisted response generation
? Chat-based user interface for interaction


The solution will operate securely within Brightter's Microsoft ecosystem and will be accessible to authorized internal users.

5.2. Module-wise Functional Workflow
5.2.1. User & Access Management Module
5.2.1.1. Overview:

This module governs how Brightter users securely access and interact with the chat-based knowledge retrieval platform. It ensures authenticated access to the system and controlled usage of internal knowledge sources.

Given that the platform provides access to historical RFP responses and advisory content, it is critical that only authorized internal users can access the system. This module ensures that system access is secure and traceable.

5.2.1.2. Functional Capabilities
? Organizational SSO-based authentication
? Role-based access control (Internal User / Admin)
? Secure session management
? Basic user activity tracking
5.2.1.3. Workflow
? User authentication via organizational login
? Role assignment (Writer / Approver)
? Permission enforcement:
? Writers can create and edit drafts
? Approvers can review and finalize
? User-specific dashboards showing:
? Draft documents
? Pending approvals
? Recently completed documents
? Activity logging:
? Document creation
? Edits
? Approval actions
5.2.2. SharePoint Integration & Knowledge Ingestion Module
5.2.2.1. Overview:
This module connects the application to Brightter's SharePoint repositories and transforms historical RFP and proposal documents into a searchable knowledge base. It enables the system to retrieve relevant content from previously stored documents.

The module ensures that institutional knowledge stored within SharePoint becomes accessible through contextual AI-based retrieval.

5.2.2.2. Functional Capabilities
? Secure SharePoint connection
? Configurable document library access
? Text extraction from Word and PDF documents
? Content normalization and segmentation
? Semantic indexing of extracted content
? Periodic repository synchronization (if enabled)
5.2.2.3. Workflow
? System connects to designated SharePoint libraries
? Repository access permissions validated
? RFP and proposal documents identified
? Text extracted from documents
? Content segmented into logical sections
? Content normalized for indexing
? Indexed into searchable knowledge store
? Index updated when new documents are added (if enabled)
5.2.3. External Data Integration Module
5.2.3.1. Overview

This module enables integration with approved external websites or portals via API to supplement internal SharePoint knowledge. It allows structured data from authorized external sources to be incorporated into the searchable knowledge base.

This ensures that both internal and approved external information can be used during AI-assisted response generation.

5.2.3.2. Functional Capabilities
? Secure API-based integration
? API authentication handling
? On-demand or scheduled data retrieval
? Data validation and normalization
? Indexing for unified search
5.2.3.3. Workflow
? System connects to approved external APIs
? API authentication validated
? Data fetched from designated endpoints
? Retrieved data validated for completeness
? Data normalized into internal structure
? Indexed into searchable knowledge store


? Content made available for retrieval during user queries
5.2.4. Knowledge Retrieval & Semantic Search Module
5.2.4.1. Overview

This module enables contextual search across indexed internal and external knowledge sources. It interprets user questions in natural language and retrieves the most relevant content based on semantic similarity.

Unlike keyword search, this module focuses on contextual understanding of the user query.

5.2.4.2. Functional Capabilities
? Natural language query processing
? Semantic similarity search
? Contextual content ranking
? Retrieval of relevant content segments
5.2.4.3. Workflow
? User submits question in chat interface
? System processes natural language query
? Query converted into semantic representation
? Contextual search executed across indexed content
? Relevant document sections identified
? Top relevant content selected
? Retrieved context passed to AI response module
5.2.5. AI Response Generation Module
5.2.5.1. Overview:

This module generates consolidated responses based strictly on retrieved internal and approved external data. The AI acts as a knowledge assistant, synthesizing relevant content into a structured answer displayed within the chat interface.

The system grounds responses in indexed data sources to maintain alignment with
Brightter's institutional knowledge.

5.2.5.2. Functional Capabilities
? Context-based prompt construction
? Grounded response generation
? Consolidated answer formatting
? Chat-based response presentation
? Query refinement support

6.2.5.3. Workflow

? System receives:
? User query
? Retrieved SharePoint content
? Retrieved API-based content (if applicable)
? Structured prompt constructed
? AI generates a consolidated response
? Response displayed in chat interface
? User reviews generated response
? User refines query if needed
? Updated response generated upon new query
5.2.6. User Interaction & Offline Utilisation Module
5.2.6.1. Overview:

This module supports how users consume generated responses and use them in their existing proposal preparation process. The system does not create or manage proposal documents internally. Users manually transfer generated content into offline documents.

5.2.6.2. Functional Capabilities
? Chat-based response viewing
? Manual copy functionality
? Multi-query interaction support
? Session-based query continuity
5.2.6.3. Workflow
? User reviews generated response
? User copies relevant content
? User pastes content into an offline document
? User prepares final proposal externally
? The user may return to the system for additional queries

14. Change Management
INT. has a formal change control process in fixed cost mode to ensure the impact of final delivery is not impaired. Well-documented scope changes help prevent misunderstanding and ensure that all parties clearly understand the impact on the timeframe, cost, and deliverables that a scope change may have.
The Change Management process has two components to manage changes within the project environment:
- The Change Request Process
- The Change Approval Process
The Change Request Process is designed to manage changes to the project goals, deliverables, timeline, or design specifications. A Change Request does not necessarily mean a monetary impact on Customers - that depends on the degree to which the scope is changed; however, all changes, large and small, are made via the Change Request process. To prevent misunderstandings, other forms of communication by any party, including, but not limited to, verbal discussions, meeting minutes, written or electronic memoranda, and presentations, do not constitute a proper Change Request.
The Change Request Process could be used to implement any permanent change in the scope of the overall program, or for any one-time or out-of-scope work associated with a specific project. Depending on the change or work to be performed, a Change Request may or may not result in a pricing adjustment or a single service charge.
The Change Approval Process provides the mechanism to accept and formalise the change requests. Specific procedures associated with the Change Approval Process are triggered upon submission of a Change Request Form to the INT. Project Manager. These could be fresh approvals for additional resources or funds, revisions to plans, schedules, etc.
